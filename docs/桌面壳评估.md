# 桌面壳评估（V1.0 最后一项）

**结论（2026-11-13）：MVP/北极星不需要桌面壳；打包是分发阶段的事。当前形态 = 浏览器看板 + 手机审批 PWA + 聊天工具本体，已全部验收。**

## 本机事实

- Rust 工具链缺失（rustc/cargo 均不存在）→ **Tauri 当前不可构建**
- Electron 路线无外部依赖（Node 生态内，仓库有 Hermes Studio 先例）

## 两方案对比

| | Tauri | Electron |
|---|---|---|
| 产物体积 | ~5-10MB | ~150MB+ |
| 内存占用 | 低（系统 WebView） | 高（捆绑 Chromium） |
| 解除阻塞 | `winget install Rustlang.Rustup` 一次安装（约 10 分钟） | 立即可行 |
| 打包脚本 | cargo/tauri.conf.json + 前端指向 packages/server/public | electron-builder + 主进程 spawn `node packages/server` |
| 团队先例 | 无 | Hermes Studio |

## 实战记录（2026-11-14 夜）

Electron 脚手架已就位（packages/desktop/main.mjs：内核内嵌+窗口，正确代码）。首跑调试发现三层环境坑：
1. Electron 33 内嵌 Node 20 无 node:sqlite（内核存储依赖）→ 需 Electron 36+
2. Windows 下 electron postinstall 二进制下载需 ELECTRON_MIRROR=npmmirror
3. **Electron 36 官方源二进制同样段错误（Segfault）**——镜像损坏假说排除（官方源复现），定性为本机系统（Windows 内部版本 26300）与 Electron 打包 Chromium 的兼容问题。⇒ **Tauri 路线反而被看好**：走系统自带 WebView2，完全绕开打包 Chromium；代价是需装 Rust（rustup 一次）。Electron 路线待白天桌面机带显示调试或换旧版 Electron（33 曾能跑到 JS 报错——说明 33 的 Chromium 能起，只有 node:sqlite 版本差）

## 解除阻塞路径（分发阶段再做）

1. **Electron 赶工线**（半天）：主进程 spawn HiveServer 子进程 → BrowserWindow 加载看板 → electron-builder 出 exe。托管凭据代理与 .env 同现状。
2. **Tauri 正式线**（1-2 天）：装 rustup → tauri.conf 指向 `http://127.0.0.1:<port>` 或内嵌静态页 + sidecar 起 node 服务。
3. 壳内安全不变：凭据代理 127.0.0.1 绑定、事件流审计、审批门全部在内核——壳只负责"装上像 App"。

## 与北极星的关系

北极星 TTFD ≤ 30 分钟的口径是「装上 → 聊天发一句话 → 交付」——聊天工具本身就是移动端入口，壳不参与验收路径。**桌面壳对北极星是零阻塞项。**
